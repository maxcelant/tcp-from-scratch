Lesson 04 · The IP layer

Serializing IPv4 + ICMP echo

Two things in this lesson:

  1. Add a Marshal method to your IPv4 header so you can write packets, not just read them.
  2. Use it to write an ICMP echo responder — a binary that reads packets from the TUN device and replies to pings. This is your first program that sends packets.

When it works, you'll be able to ping 10.0.0.2 and see replies generated by your own code. Concretely demonstrable progress.

Background

Marshaling IPv4

Marshal is the inverse of Parse. Given a Header value, write the 20 bytes in the correct wire format into a buffer. The two non-obvious parts:

  1. Compute the header checksum. Zero the checksum field, write the rest of the header, run checksum.Sum over those bytes, then write the result into the checksum field. (Or equivalently: write everything with checksum=0, sum, then patch.)
  2. Total Length must be set by the caller before Marshal. Marshal serializes what's in the struct; it doesn't know how big your payload will be. Document this in the doc comment.

ICMP echo (ping) at a glance

ICMP echo lives at IP protocol number 1. Format (RFC 792):

  • Type=8: echo request. Type=0: echo reply. Code is always 0 for both.
  • Identifier and Sequence Number are echoed back verbatim so the sender can match requests with replies.
  • Data is also echoed back verbatim. ping typically fills it with a timestamp + a pattern.
  • Checksum covers the ICMP header + data (NOT the IPv4 header — that has its own checksum).

To respond:

  1. Receive a packet.
  2. IPv4-parse it; check protocol == 1 (ICMP).
  3. Look at the payload (ICMP message). Check type == 8 (echo request).
  4. Build a new ICMP message: set type=0, copy the rest, recompute ICMP checksum.
  5. Build a new IPv4 header: swap src/dst, set protocol=1, set Total Length, recompute IP checksum.
  6. Write the resulting bytes to the TUN device.
Why keep it inline

That's it. No ICMP package, no protocol abstraction — keep it inline in cmd/icmp-echo/main.go. We're not building a generic ICMP stack; we just want ping to work as a smoke test.

What to implement

Add to internal/ipv4/header.go

go
// Marshal writes h into dst in wire format and returns the number of bytes
// written. The caller must set h.TotalLength and h.Protocol before calling.
// dst must be at least HeaderMinLen bytes; returns ErrTooShort otherwise.
// Marshal computes and fills in the header checksum (RFC 791 §3.1).
func (h Header) Marshal(dst []byte) (int, error)

Also add (or extend the existing) tests in internal/ipv4/header_test.go:

  • Round-trip: Parse a known good fixture, Marshal it back into a buffer, assert the bytes match the original (the checksum must come out identical because the inputs are identical).
  • Marshal with a too-small dst returns ErrTooShort.

cmd/icmp-echo/main.go

A main() that:

  1. Opens tun.Open("tun0").
  2. Loops:
    • Reads one packet into a 1500-byte buffer.
    • Parses the IPv4 header.
    • If Protocol != ProtoICMP, log and skip.
    • If the ICMP type byte (payload[0]) is not 8, log and skip.
    • Constructs the reply (in-place mutation is fine, or build into a separate buffer).
    • Writes the reply to the device.
  3. On SIGINT, closes cleanly.

Use stdlib log for output. Keep the main file under 150 lines.

Common bug

Writing the response with the wrong total length, or forgetting that the IPv4 Total Length field includes the header AND the payload, not just the payload.

Zero the checksum first

Set the checksum field to 0 before computing the checksum (RFC 791 §3.1). Write the checksum into the field, then return. This applies to both the IPv4 header checksum and the ICMP checksum — each is computed over its own region with its own checksum field zeroed.

How to test it yourself

bash
go build ./cmd/icmp-echo
sudo ./scripts/net-up.sh
sudo ./icmp-echo &

# Ping your stack's address. The kernel routes it to tun0; your program replies.
ping -c 3 10.0.0.2

# You should see 3 replies with RTT.
sudo ./scripts/net-down.sh

Use sudo ./scripts/tcpdump.sh (or make tcpdump) in a third terminal to watch packets fly past in real-time.

Done when

  • Header.Marshal round-trips: Parse → Marshal yields identical bytes for both testdata/ipv4-basic.hex and testdata/icmp-echo.hex.
  • cmd/icmp-echo builds.
  • The integration check scripts/check-L04.sh brings up tun0, runs your icmp-echo binary, pings 10.0.0.2 3 times, and confirms at least one reply (parsing ping's "N received" line).
Stuck? Reveal hints (they escalate)
  1. Marshal writes the header into a caller-supplied byte slice and returns the number of bytes written. The caller is responsible for sizing the buffer (≥ 20 + options, which we don't use, so just 20). Returning int instead of allocating means zero garbage on the hot path.
  2. Set the checksum field to 0 before computing the checksum (RFC 791 §3.1). Write the checksum into the field, then return.
  3. An ICMP echo reply is just an echo request with type=0 (instead of 8). The identifier, sequence number, and payload are copied verbatim. ICMP has its own checksum — same algorithm (RFC 1071), covers the whole ICMP message.
  4. When you build the reply IPv4 header: swap src and dst, decrement nothing (TTL is fine), bump the IP ID if you want (some kernels do, doesn't matter for correctness), and recompute the header checksum.
  5. Common bug: writing the response with the wrong total length, or forgetting that the IPv4 Total Length field includes the header AND the payload, not just the payload.
